# oan_dev deploy (Helm)

The `develop` pipeline deploys the Helm release `grievance` (chart `helm/oan-grievance-service`, values
`helm/environments/dev/oan-grievance-service.yaml`) to namespace `grievance` on the oan_dev k3s node. It runs after
the RKE2 deploy and does not block it. The stages are `Push image + seed (helm)`, `Package chart`,
`develop → oan_dev (helm)` and `Publish chart`. The deploy runs on a VPN agent (label `oan-ci-deploy`) with a
kubeconfig, not an SSH key, through `ci/deploy-helm-dev.sh`.

Site `grievance-service.development.oanstaging.com`, database on the shared PostgreSQL (namespace `frappe-common`).

## What the pipeline builds

| Artifact      | Name                                                         | Tag                                                     |
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| Service image | ECR `oan/oan-grievance-service/grievance-service`            | `<__version__>-develop.<build>`, e.g. `0.0.1-develop.7` |
| Seed image    | ECR `oan/oan-grievance-service/grievance-seed`               | same tag                                                |
| Chart         | `oan-grievance-service` in `repository/develop/` of oan-helm | same version                                            |

The service image is the one the RKE2 stage already built (the layered image with `oan_auth_service` and this app),
tagged a second time. The seed image holds `oan-seed/grievance` of openg2p-data at the commit `develop` points at.
The pipeline creates the two ECR repositories if they are missing, which needs `ecr:DescribeRepositories` and
`ecr:CreateRepository` on the `aws-ecr-creds` credential.

## Secrets

Generated by the chart once and kept across upgrades: `oan-grievance-admin` (Administrator password),
`oan-grievance-jwt` (RSA key that signs access tokens), `oan-grievance-secret-key` (site `secret_key`).

Created outside Git, in namespace `grievance`:

- `oan-frappe-common-db` (key `password`): copied from `frappe-common` by the deploy script.
- `oan-grievance-seed` (key `password`): password of the demo users. Optional; without it they have no password.
- `oan-grievance-sentry` (key `dsn`): optional.

## ClamAV

`templates/clamav.yaml` runs a ClamAV daemon as `<release>-clamav` (image `clamav/clamav-debian`), and the site
sets `grievance_clamav_host` to it. It asks for 1.5 GiB of memory and signatures load in one to two minutes after
the pod starts. Set `clamav.enabled=false` to run without it: attachment scans then retry until a scanner exists.

## Site settings

`iamServices` in the chart values lists `OAN IAM Service` rows (the login options). When it is set, a Job
writes them into the database on every install and upgrade (`oan_grievance_service.setup.site_settings.sync`).
It is empty on dev: the rows come from the seed.

## The identity

`ci/cluster/oan-dev-deployer.yaml` creates namespace `grievance` and ServiceAccount `jenkins-grievance-deployer`:

| Namespace       | Access                                 | Used for                   |
| --------------- | -------------------------------------- | -------------------------- |
| `grievance`     | built-in `admin` role                  | the `grievance` release    |
| `frappe-common` | get Secret `oan-frappe-common-db` only | copy the Postgres password |

It cannot touch anything else.

## Set up (once per cluster)

1. On the node (`ssh oan_dev`), with `ci/cluster/` copied over:
   `bash ci/cluster/bootstrap-oan-dev.sh /tmp/oan-dev-grievance.kubeconfig [https://<api-address>:6443]`.
2. Jenkins → Manage Jenkins → Credentials, in a scope the grievance job can see → Add → **Secret file**, ID
   `oan-dev-grievance-kubeconfig`, upload the file. Delete every local copy of it.
3. Add the two new ECR repositories to the pull permission of the node role (`oan-services-dev-ecr-pull`:
   `ecr:BatchGetImage`, `ecr:GetDownloadUrlForLayer`, `ecr:BatchCheckLayerAvailability`), unless it covers `oan/*`.
   The node pulls with its own IAM role, see the a2c service's `docs/operations/oan-dev-deploy.md`.
4. Optional: `kubectl -n grievance create secret generic oan-grievance-seed --from-literal=password=<password>`.
5. `gatewayAccess` opens node port 30800 (gunicorn) and 30900 (socket.io) for the central APISIX gateway. Allow them
   in the node's security group from the gateway cluster's addresses only, and route a public host to them.

Never commit the kubeconfig, its token or `ca.crt`.

## Not set up

- `iamServices` and an APISIX route for the new host.
